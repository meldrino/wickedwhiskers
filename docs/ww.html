  • LMB click — walk to a spot, or interact with an object once within ~1.8 m (walk-then-interact).

Core Concept

Wicked Whiskers is a mischievous, chaotic, pun-filled cat adventure set on a farm and nearby town. The tone is humorous, cheeky, and full of feline wordplay. The player (or main cat) is clever, resourceful, and always up to trouble.

Setting

  • A working farm with a farmhouse, shed, fields, trees, and roaming wildlife.
  • A nearby town inspired by Dick Whittington-style folklore.
  • Day/night cycle affects access and danger.

Main Gameplay Themes

  • Mischief, chaos, cleverness, and feline ingenuity.
  • Resource gathering (string, sticks, food).
  • Crafting silly contraptions (ladders, convoluted mouse traps).
  • Quests from the wise old cat.
  • Trading caught animals for gold.
  • Progression through 9 lives.

Dumbleclaw — The Wise Old Cat (Quest Giver & Trader)

The wise old cat is named Dumbleclaw. He looks like a feline version of Albus Dumbledore (headmaster of Hogwarts) — long grey beard, half-moon spectacles, and a robe-like air of calm authority. "The purr-ofound mentor with nine lifetimes of wisdom."
  • Lives behind the farmhouse.
  • Gives advice, quests, and challenges.
  • Buys spare mice or birds for gold.
  • Provides lore and hints.

Cat Behaviours & Activities

1. Catching Mice — convoluted mouse trap ONLY

Mice hide around the farm. They cannot be caught by chasing — you must build a convoluted mouse trap out of string and sticks (think the board game Mouse Trap: tipping buckets, running boots, rolling balls).

"A fur-midable hunter with claw-some inventions."

2. Catching Birds — ladder ONLY

Birds perch in trees. They cannot be caught by climbing manually — you must build a ladder, also out of string and sticks, to reach them.

"Purrfectly engineered chaos."

3. Gathering Materials

  • String — found in the shed.
  • Sticks — found on the ground around the farm.
  • Food — scavenged from the farmhouse kitchen (daytime only).

"Pawsitively resourceful."

4. Sleeping in the Shed

  • Shed acts as a safe zone.
  • Restore health/lives.
  • Store materials.

"A whisker-twisting nap spot."

Grass — how we finally got it right (the nightmare)

Grass took DAYS and several rejected approaches. This is the full history plus the working recipe so nobody ever re-lives it. Final system = chunked full-geometry tufts, one shared shader, no impostor, no baked texture. This is what ships.

  • DEAD END 1 — baked texture sheet (07/08, REJECTED "blades are just blobs"): cover a 1x1 tile with dense tufts, bake a top-down ortho render to one 1024x1024 texture, use it on a deformable plane. FAILED because a top-down ortho bake flattens 3D blades into pure vertical projections — at 1 texel/m they crush under the sward discs and read as flat green blobs. Do not go back to this.
  • DEAD END 2 — impostor far plane (09-10/08, THE ROT): chunked near/mid blades + a terrain-draped far impostor plane with its own shader. The impostor caught full sun while real blades self-shadowed, so the far field read LIGHTER (even after distance-darkening hacks). Ground was "unacceptable". DELETED.
  • THE WIN — one shared full-geometry shader (11/08 onwards): restored the USER-APPROVED tuft look (hexaquo.at tutorial, Karl Bittner, CC-BY-SA, parts 2+3 = the same architecture we already had) INSIDE the chunked streamer, engine-native tiers, every chunk renders real tufts.
  • Per-tuft anatomy (grass_chunk.gd VEG): flat sward disc (UV.x=2 shader marker, radius 0.125, dark = base*0.6, radial vertex shading) + 16 outer + 8 inner thin RIBBON blades (4 vertex rings = 6 tris, half the old box) with UV.y = 1 at base / 0 at tip so the shader's bottom_to_top gradient works. Tapered tips (half-width * (1 - 0.6*t)).
  • The 2 cm cap math: local blade tip = base_off 0.008 + max_h 0.008 = 0.016 m, x shader size_large 1.15 = 0.018 m ≈ 2 cm (mowed lawn). disc_off 0.006. If you ever raise it, hscale sweeps already proved ~8 cm reads as "a field of grass" and costs nothing.
  • Shader (grass.gdshader): cull_disabled with the if (!FRONT_FACING) NORMAL = -NORMAL fix; vertex() sizes by seamless world-space patch_noise (clumps), bends tips by blade_bend * pow(bottom_to_top, 2.0), gusts via scrolling wind_noise with direction rotated world→instance by inverse(MODEL_MATRIX); fragment() AO = bottom_to_top - wind*affect (tips bright/base dark), 3-scale noise for mottle (6 m patch + 1.4 m + 0.3 m + per-pixel turf grain at world_vertex.xz/0.05), BACKLIGHT translucency. Unit trap: tutorial bend/wind values assume UNIT-height blades; ours are metre-scaled, so blade_bend 0.02 and wind_strength 0.01 (not 0.35/0.12).
  • Chunked streamer (grass_system.gd): 5x5 m chunks (CHUNK_SIZE 5.0, STREAM_RADIUS 92, FENCE_HALF 25 — grass ONLY inside the 50x50 fence, outside is bare terrain). Macro 10x10 far chunks were TRIED and REVERTED (caused grass to disappear on fast turns) — stay 5x5 everywhere. Two stream centers: camera + Mouse.
  • Placement: MultiMesh via set_instance_transform — the .buffer array path SILENTLY FAILED ("painted grass" bug), never go back. Budget BUILD_PER_FRAME 6000, _mm.visible=false until the array is placed (this causes a disappearing-on-fast-turn artifact; raise the budget or keep _mm.visible=true if it returns). Adaptive probe placement near (PROBE_STEP 0.035, COVER_RADIUS 0.02) + jittered grid far (TUFT_SPACING 0.12). Reject terrain above rock_start+0.3, GrassExclusion rects, water.
  • Vision loop lesson: qwen2.5vl:3b "field of grass" read is driven by BLADE SIZE IN FRAME. 2 cm = "green carpet"; ~8 cm = "visible blades". Calibrate against a real photo before trusting the model. qwen2.5vl:3b is unreliable at describing scenes — pixel/ probe stats are the primary signal, vision is corroboration only.
  • Godot gotchas hit: FastNoiseLite has no seamless property (only NoiseTexture2D); fragment built-in is COLOR not VERTEX_COLOR; no return in Godot 4 fragment shaders; SurfaceTool has no get_vertex_count() in 4.7.1; user args need the -- separator (--path X -- --fpsbench).
  • Backup rule (user): every approved look = a committed + pushed screenshot (<seq>_<mode>_<camera>_<state>.png, commit message = same tag) so any look is fetchable from git history as a revert map.

Character pipeline — how WW (the cat) was made in Blender

WW is built procedurally in Blender via Python, not hand-modelled and not AI-generated (Meshy/Tripo were evaluated and rejected: no API, user cannot view AI images, no licence/consistency control). The generator is fully re-runnable and deterministic. This is the path to reuse for Dumbleclaw's rework and any future NPC.

  • Files: tools/blender/gen_ww.py (the cat, v0.3) and tools/blender/ww_style.py (SHARED style spec — palette + roughness/metallic + primitive helpers: sphere, capsule, tapered_tube, subdiv, glTF export). Trees = gen_trees.py, rocks = gen_rocks.py, all built on ww_style.py so everything matches. Unit convention: generators build in "cat units" (~2 m tall cat); main.gd scales at placement.
  • Run it: "C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" --background --python gen_ww.py → outputs assets/WW.glb (rigged, +Y up, forward -Z). After re-running, reimport in the Godot editor (delete .godot/imported to force a full reimport) — stale zombie Godot processes hold the old import; the launcher kills them.
  • WW.blend is saved OUTSIDE the project (C:\crypto\wicked-whiskers-blender-out\WW.blend): a .blend inside res:// breaks Godot's importer without a configured Blender path.
  • How it builds (gen_ww.py): (1) geometry = one UNIONED fur body (boolean EXACT solver on spheres/capsules/tapered tubes: body, head, ears+inner cups, legs, tail curve, muzzle, belly) + SEPARATE feature meshes (nose, almond flattened eyes with pupils + glints, satchel box + strap, 3 whisker strands per cheek) + SEPARATE arm meshes (tapered tubes sunk into the chest, held outside the body so auto-weights pin them to the arm bones); (2) armature with stable bone names (Root/Pelvis/Spine/Chest/Neck/Head + L/R UpperArm/ Forearm/Hand/Thigh/Shin/Foot/Toe/Ear + Tail01-03); (3) parent_set ARMATURE_AUTO (automatic weights); (4) subdiv 3 on the body, 2 on arms, shade_smooth; (5) paint_cream_faces assigns the CREAM material to faces near ref points (muzzle/belly/toes) AFTER subdiv; (6) glTF export.
  • Tail technique (5 spheres → 1 tapered tube): the tail was originally 5 spheres stacked on top of each other and looked wrong. It is now ONE tapered_tube following a curved 3D path (9 path points, per-point radius shrinking 0.14 → 0.028, from pelvis up over the back). Same primitive = the arms (each arm = one tapered tube + a paw sphere, smooth surface instead of stacked capsules/spheres) and the whiskers (thin tapered strands). This "single tapered tube along a path, radii per point, cap_tip" is THE trick for smooth organic limbs — use it for Dumbleclaw's limbs too.
  • KNOWN BUG (fix next cat pass): build_armature() bone positions for the arms are still at the OLD coords (0.48-0.52) — the arm MESHES moved to 0.68-0.76. Bones and meshes must match or auto-weights drift. The 3b4edf9 commit rebuilt arms as smooth tapered tubes at the shoulder (were floating capsules).
  • WW.glb is 37 MB — suspected embedded uncompressed textures or dense keyframes; check in Blender (resize to 1024, prune keyframes) before shipping.
  • Rigging facts (player.gd): set_bone_pose_rotation(IDENTITY) aligns a bone with its PARENT frame, NOT the rest pose — pass get_bone_rest(idx).basis to return to rest. Walk is a procedural sine trot (LF+RH diagonal, knees fold on the swing leg, body sinks to keep paws planted) — a keyframed Blender walk cycle is the future upgrade.
  • Style consistency rule (user): new props must come from the Kenney Nature Kit (C:\crypto\world\kenneys nature kit) — never mix packs. Character/NPC upgrades (like Dumbleclaw's beard) are code-built primitives in dumbleclaw.gd today; the Blender pipeline above is the upgrade path for a proper Dumbleclaw model + future NPCs.
  • Fallback: docs/cat_prompts.md keeps the Meshy/Tripo prompts as a fallback if AI variants are ever wanted (free tier = CC BY 4.0 + attribution).

Lessons (recurring mistakes to never repeat)

  • This page is for AI, not the public. /forai/ww.html is the AI reference; /ww.html is the public marketing page. On 2026-08-13 the public page was found copied over this reference page (same title, public styling, no noindex) — a full overwrite that lost the design/canon/build-status content. Recovery: a .bak saved 60 ms before the overwrite (ww.html.bak.202608111715). Rule: never copy the public page over the forai page; keep .bak before any deploy; the forai page stays dark-styled, noindex, and titled "wicked whiskers reference".
  • This page is the durable memory. big-pickle session context can be lost or compacted and the YAMLs get trimmed. Durable decisions, canon, and build facts live HERE. If this page is ever lost, recovery source = the newest .bak in /var/www/html/forai/ and the working copy /home/andy/ww.html.
  • Interaction range is not interaction point. Proximity is measured against specific points (hinge / far end / panel centre), not the whole object. A 2.9 m-wide gate needs all three points or the middle becomes a dead zone. Fix range bugs by checking the pick math, not by assuming the object is one point.
  • Godot 4 API is not Godot 3. normal_map on SpatialMaterial is now normal_enabled + normal_texture; MeshInstance3D.surface_get_material() is on mesh; look_at needs the node added to the tree first. Watch the console, fix each warning — they are real API drifts.
  • Click priority: interactables beat animals. If a fish sits near the gate, a gate click must win or the cat pounces into the lake. Interactable pick runs before fish pick in _handle_click_at.
  • No image input, no visual claims (2026-08-13). An agent that cannot see images must NEVER ship procedural visual work as "done". Render frames, run a vision-capable reviewer (gemini-flash via C:\crypto\bigpickle\gemini-vision.ps1), and let the USER judge aesthetics before claiming a result. The cutaway consumed hours because unverified procedural geometry was built blind and only reviewed by an over-lenient model.
  • Paws need finger anatomy, not claws (2026-08-13). A paw "manipulating" a padlock reads as waving a paw around the lock when the digits are claw-toes hooking up from below, or when the paw and dial move independently. The fix that reads correctly: 3 fingers + 1 thumb wrapping the dial's top edge, and the dial + paw rotate RIGIDLY together around the dial axis so the paw visibly drives the turn (grip-turn).
  • Git history two-line save (2026-08-13). The cutaway work lived on a detached HEAD while origin/master had diverged grass work. Save before a compact = commit + push as a NAMED BRANCH (no force-push needed): cutaway-finger-anatomy. Origin/master was left untouched; reconciling the two lines is still an open user decision. Also: pushing a branch full of committed screenshots packs ~160 MB — allow minutes, don't kill it (each kill restarts the pack).
