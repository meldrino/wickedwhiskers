This section applies to EVERY asset for the game Wicked Whiskers. It is followed by an asset-specific brief.

========== VISUAL LANGUAGE (Wicked Whiskers) ==========
Style: chunky, rounded, toy-like low-poly cartoon. Kid-friendly farm-game look. Simple readable silhouettes, slightly exaggerated proportions. NOT photorealistic. Flat solid colours - no textures, no image files, no UV work. Materials are plain Principled BSDF with Base Color + Roughness only.

Game palette (hex -> linear-ish sRGB floats):
- Tractor red   #D12E21 = (0.82, 0.18, 0.13)
- Wood brown    #8B5A2B = (0.55, 0.35, 0.17)
- Dark grey     #333338 = (0.20, 0.20, 0.22)
- Near black    #141417 = (0.08, 0.08, 0.09)
- Light grey    #9A9AA0 = (0.60, 0.60, 0.63)
- Cream         #F5F2E6 = (0.96, 0.95, 0.90)
- Leaf green    #4C9A3F = (0.30, 0.60, 0.25)
- Sky/window    #A8D8E8 = (0.66, 0.85, 0.91)
- Warm light    #FFF2CC = (1.00, 0.95, 0.80)
Roughness guide: matte surfaces 0.6-0.95, plastic/painted metal 0.35-0.5, glass/windows 0.15, lights 0.3.

Orientation contract (unless the asset brief says otherwise):
- Up is +Y, FRONT of the asset faces +Z, origin at ground level centred left-right.
- Real-world scale in metres (a fence plank ~1 m long, a tractor ~2 m tall).

========== BLENDER 5.2 API - VERIFIED FACTS (violating these crashes the script) ==========
Verified against Blender 5.2.0 LTS on this machine. Follow EXACTLY:

bmesh.ops functions that EXIST: create_circle, create_cone, create_cube, create_grid, create_icosphere, create_uvsphere, contextual_create, create_vert.
- bmesh.ops.create_box DOES NOT EXIST. Use bmesh.ops.create_cube(bm, size=1.0) - size is the FULL edge length of the cube; scale afterwards or transform mesh data to the size you want.
- bmesh.ops.create_cone(bm, cap_ends=True, cap_tris=False, segments=24, radius1=R, radius2=R, depth=D) - keywords are radius1/radius2/depth. diameter1/diameter2 DO NOT EXIST. radii are RADII not diameters.
- bmesh.ops.create_uvsphere(bm, u_segments=24, v_segments=16, radius=R).
- There is NO bmesh torus op. For rings/arches use bpy.ops.mesh.primitive_torus_add(major_radius=..., minor_radius=..., location=...) which DOES exist, or build arcs from short box/cylinder segments.

Object creation pattern (safe):
    me = bpy.data.meshes.new(name); bm = bmesh.new(); ...build into bm...; bm.to_mesh(me); bm.free()
    ob = bpy.data.objects.new(name, me); bpy.context.collection.objects.link(ob)
NEVER use bpy.data.meshes.new_from_mesh() - removed in Blender 5.
To position/orient a part prefer transforming MESH DATA (me.transform(Matrix.Translation(...))) or building vertices at final world coordinates, keeping OBJECT transforms at identity - unless the brief says a part needs identity-local axes for game animation (e.g. wheels spin around local X).

Materials:
    mat = bpy.data.materials.new(name); mat.use_nodes = True
    bsdf = mat.node_tree.nodes["Principled BSDF"]
    bsdf.inputs["Base Color"].default_value = (r, g, b, 1.0)
    bsdf.inputs["Roughness"].default_value = 0.5
    ob.data.materials.append(mat)

FORBIDDEN (they crash or misbehave headless):
- bpy.ops.wm.save_as_mainfile / any .blend saving
- bpy.ops.render.render / cameras / lights
- bpy.ops.object.* selection-dependent calls without context
- bpy.data.meshes.new_from_mesh()
- any addon/import beyond bpy, bmesh, mathutils

Output contract:
- Export GLB to EXACTLY the placeholder path given in the brief, verbatim:
    bpy.ops.export_scene.gltf(filepath="__GLB_OUT__", export_format='GLB')
- Print exactly ASSET_BUILT on success.
- Print overall bounding-box dimensions across all mesh objects: print("DIMS Vector((dx, dy, dz))")
- Keep parts as separate named meshes (especially anything the brief names for gameplay).
